# Locky — UX 실사용 계약

## 제품 목적과 행동 위계

스마트폰 사용을 기계적으로 차단하는 것이 아니라 사용자가 열기 전 목적을 의식적으로 선택하거나 그냥 종료할 수 있게 하는 개인 도구다. 처음 사용자도 시작 화면에서 주요 선택을 알아볼 수 있어야 한다. 노트·ChatGPT·사전 같은 상시 도구와 '목적 선택' 영역을 시각적으로 구분한다. 목적 선택에 별도 확인 버튼이 불필요한지 실제 상태 전이와 재진입 위험에 따라 판단하고, 불필요한 클릭 단계를 기본으로 추가하지 않는다. 의미 없이 빈 공간을 채우거나 기능을 수직 나열하기만 하지 않는다.

## 필요한 사용자 작업의 완결성

사용 목적 프리셋·사용자 정의 목적의 생성/선택/편집/삭제, 앱별 예산·집중시간 수정, 메모·체크리스트 관리, ChatGPT 대화 생성·열기·삭제와 질문 제출, 사전 선택, 브리핑 열람·기록 복사·내보내기가 실제로 완료되는지 확인한다. 필요한 항목의 삭제·편집 경로를 빠뜨리거나 하위 메뉴 깊이 숨기지 않는다. 모달/설정 화면에서 저장·취소·닫기가 긴 스크롤·키보드·작은 창 때문에 가려지지 않게 한다.

## 자주 발생한 실패에 대응하는 수용 시나리오

시작 화면에서 질문을 입력하면 질문이 저장된 동일 채팅방을 열어야 하며 비어 있는 새 채팅방으로 이동해서는 안 된다. 시스템 최근 앱 목록에서 Locky로 돌아갈 때 기존 task와 상태가 정상 복원되어야 한다. 전경 앱 사용시간은 화면 꺼짐·알림창·최근 앱·보조 시스템 앱으로 인한 중복 집계에 주의하며, 앱에서 제공하는 제외 정책이 있다면 선택·적용·복원을 확인한다. 타이머 알림/NowBar는 기기·OS별 실제 지원을 구분하고 구현이 불가능한 UI를 지원한다고 주장하지 않는다.

브리핑에서는 시간 순서·기록 정확성·복사/내보내기 결과를 확인한다. ChatGPT 답변의 Markdown이 원시 기호로 노출되거나 출처 접기/펼치기 조작이 고장 나지 않는지 확인한다. 접근성 권한/알림 거부, 집중시간 종료, 사용 중단·취소와 다음 앱 열기, 폴더블·다크/라이트·시스템 인셋·키보드 변화를 점검한다.

앱 설명은 `README.md`, `docs/PRODUCT_PRINCIPLES.md`와 현재 접근성/사용기록/메모/브리핑/ChatGPT 구현이 기준이다. 위 시나리오는 회귀 방지용 품질 요구이며 현재 모두 구현되어 있음을 뜻하지 않는다.
