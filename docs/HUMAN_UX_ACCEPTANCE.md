# 사람 기준 UX 검증: 검증 가능한 수용 시나리오

이 파일은 코드 리뷰 시 변경된 사용자 작업에 맞춰 선택적으로 사용하는 시나리오 모음이다. 모든 수정에 모든 시나리오를 반복하지 않는다. 자동 검증은 가능한 범위에서 활용하고, 실기기·실계정·실제 콘텐츠가 필요한 경우에는 한계와 필요한 사람 확인을 분리하여 보고한다.

## 사용자 행동을 시작부터 끝까지 검증

| 분류 | 최소 실행 시나리오 | 통과의 증거 |
|---|---|---|
| 작업 찾기 | 새 사용자가 주요 목적을 수행할 조작을 발견하는가 | 첫 화면과 다음 행동이 시각적으로 구분됨 |
| 객체 관리 | 실제 데이터 한 개 생성→열기→편집→저장→복귀→재열기→삭제/복구 | 화면·저장소에서 대상 ID와 결과 일치, 필요 조작 존재 |
| 팝업 조작 | 긴 콘텐츠와 작은 화면에서 모달 열기→편집→저장/닫기 | 버튼 접근 가능, 중첩 팝업 복귀 후 상태 유지 |
| 버튼 반응 | 탭 1회·빠른 연타·느린 처리·오류·취소 | 눌림/진행/완료 표시 및 중복 요청 방지, 실패 복구 |
| 입력 값 확정 | 색·굵기·크기·좌표·순서 변경 후 터치 종료·다시 열기 | 미리보기와 최종 반영 일치, 값 지속 저장 |
| 밝음/어두움 | 밝은 테마·어두운 테마 각각 정상/선택/disabled/에러/모달 | 읽을 수 있는 대비, 아이콘·경계·스크롤 상태 확인 |
| 협소 화면 | 작은 너비·낮은 높이, 큰 글꼴, 키보드 표시와 긴 문자열 | 내용/버튼 미가림, 도달 가능한 스크롤과 행동 |
| Android 복귀 | 다른 앱 전환→최근 앱→복귀; 시스템 뒤로·잠금→재개 | 같은 문서/방/탭, 같은 초안·스크롤·진행 위치 유지 |
| 화면 구성 변화 | 회전·폴더블 접기/펼치기·멀티윈도우 | 주요 조작 유지, 중복 생성/데이터 손실 없음 |
| 성능·제스처 | 빠른 스크롤·드래그·pinch·필기 도구 및 상태 변화 | 실제 입력 의도/좌표 일치, 작동 부드러움, 프레임 영향 확인 |
| 정보 신뢰성 | 빈 목록, 수백 건, 길고 특수문자 포함 제목, 기존 데이터 | 순서·개수·상세 정보 정확하고 잘림·침묵 실패 없음 |
| 권한·오프라인 | 거부·회수·네트워크 실패·부분 데이터 | 실패 이유, 재시도, 대체 경로, 기존 자료 무손상 |

## 검증 심도 결정

**작은 변경:** 수정된 UI 작업의 버튼→결과 확인과 바로 인접한 상태 한두 개를 점검한다. 기존 통과 결과를 재활용하고 전체 에뮬레이터·스크린샷을 강제하지 않는다.

**중요한 상호작용 변경:** 객체 생애주기, 저장·되돌림, 연타·비동기, 모달·키보드, 테마/작은 화면을 영향 범위에 따라 선택한다. 재발한 문제의 구체적인 실패 사례를 회귀 테스트 또는 수동 시나리오로 재현한다.

**화면/내비게이션 전체 개편:** 첫 진입부터 결과·편집·취소·복구까지 실제 사용 흐름을 확인한다. 화면 배치의 미학적 판단은 코드 테스트만으로 충분하지 않으므로 가능한 화면 확인 또는 사람 리뷰를 거친다.

**데이터 손실·서명·인증·결제·권한·중요한 Android lifecycle:** 위험이 크므로 단순 UX 검증보다 저장·오류·보안·호환성 검증을 강화한다. 필수 테스트를 비용 절감 명분으로 생략하지 않는다.

## 완료 보고 계약

‘구현 코드 확인’, ‘자동 테스트 통과’, ‘화면 스크린샷 검사’, ‘실기기 입력 검증’, ‘사람의 사용성 평가’를 각각 별개 사실로 기록한다. 실제로 수행하지 않은 검증은 검증 완료라고 쓰지 않는다. 검증 장비가 없어 재현하지 못한 시나리오는 별도 확인 사항으로 남긴다. 단순히 모든 버튼이 HTML에 존재한다는 검사만으로 상호작용 완결성을 증명하지 않는다.
