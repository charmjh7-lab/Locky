Locky 1.2.3

기존 설치와 같은 앱 ID(com.locky.app)와 서명을 유지합니다.

- 화면 꺼짐에서 시작화면을 한 번 준비하고 중복 화면 꺼짐은 다시 처리하지 않습니다. 화면 켜짐·인증 완료·접근성 이벤트는 같은 잠금 해제 전환 함수를 사용하며, 접근성 이벤트 안의 전면 창 중복 조회를 제거했습니다.
- 창 이벤트의 기존 100ms 병합 대기를 제거하고 화면 켜짐의 첫 잠금 확인을 바로 실행합니다. 잠금 해제가 확인되기 전에는 개인 화면을 투명·입력 불가·접근성 비노출 상태로 유지합니다.
- 잠금 해제 직후의 배경 앱 정보와 NotificationShadeWindow라는 이름만으로 전환을 종료하지 않습니다. 로키 창의 실제 포커스와 안정된 창 상태를 기준으로 종료하며, 새 시스템 창·권한창·최근 앱·수신 전화에는 양보합니다.
- 준비된 WebView를 다시 노출할 때 Chromium 재활성화·타이머 재개·레이아웃 재요청·프레임 초기화를 반복하지 않습니다. 화면 표시와 실제 렌더링 활성 상태를 구분하고 실제 pause·detach·내용 변경·렌더러 종료 시에는 필요한 준비를 유지합니다.
- 같은 화면에서도 DOM이 실제로 다시 렌더링되면 새로운 프레임을 확인합니다. 소프트웨어 렌더링, 실제 그리기 확인, 느린 콜백 복구와 초기 로드 복구를 유지합니다.
- 사전 Activity·WebView 전달·검색어 삭제, 화면 잠금과 앱 취소, 시작화면 배치·여백·메모 크기·목적 선택과 데이터 형식은 변경하지 않았습니다. 잠금 해제용 Activity·스크린샷·스플래시·페이드·표시 지연을 추가하지 않았습니다.

검증은 기존 관련 JVM 검사에 중복 이벤트·준비 프레임 재사용·실제 DOM 변경·시스템 창 양보·잠금 전 개인정보 비노출 시나리오를 추가해 실행합니다. 릴리즈 빌드는 lint와 서명·앱 ID 검사를 거쳐 게시합니다.

실기기 확인 필요: 삼성 One UI에서 지문/PIN 잠금 해제 후 다른 화면의 순간 노출과 팝업 느낌, 즉시 알림창/최근 앱/다른 앱으로 전환, 반복 화면 켜기·끄기, 장시간 꺼짐 뒤 흰 화면 여부. Android의 잠금 해제 신호 이전에 접근성 오버레이를 미리 노출하지 않으므로 시스템 잠금 해제 애니메이션과 같은 합성 프레임에 표시되는지는 자동 검사만으로 보장하지 않습니다.
