Locky 1.2.7 — 잠금 해제 창 유지 및 앱 내 진단

기존 앱 ID com.locky.app, 개인 서명, 사용자 데이터와 설정을 유지합니다.

수정한 경로

- 기존에는 잠금 해제 중 처음 보는 시스템 창 ID가 활성화되면 unlockTransition을 종료하고 SUSPENDED/alpha=0으로 갔다가 다시 INTERACTIVE/alpha=1로 돌아갈 수 있었습니다. 이제 ID 추가 자체는 인터럽트의 근거가 아닙니다. 잠금 상태·해제 진행 단계·창 역할·포커스와 명시적인 시스템 행동을 함께 판단합니다. 해제 중의 모호한 System UI 변화는 같은 전환에 귀속하며, 포커스를 가진 실제 앱의 비시스템 스냅샷 또는 실제 사용자 입력에서 전환을 끝냅니다. 권한 창·전화·최근 앱·명시적인 알림/빠른 설정 등은 기존대로 제어권을 넘깁니다. 전환 종료 후 알림창은 정상적으로 중단 처리합니다.
- 일반 오버레이는 기본 디스플레이의 잠금화면 아래에서 touchable/nonfocusable 창으로 준비합니다. 잠금 중과 미준비 상태에서는 GateSurface가 WebView 입력을 차단하고 접근성 자손 노출도 막습니다. SHOW_WHEN_LOCKED/DISMISS_KEYGUARD는 사용하지 않습니다. 실제 시스템 중단에는 NOT_TOUCHABLE로 제어권을 넘깁니다.
- 준비된 일반 창의 정상 BEHIND_KEYGUARD → INTERACTIVE에서는 alpha=1, visibility, 크기, 종류뿐 아니라 WindowManager 입력 플래그도 유지합니다. 이 전환을 위한 updateViewLayout 호출 자체가 없어졌습니다. 버튼 터치를 즉시 전달하며 첫 터치를 포커스 획득용으로 소비하지 않습니다.
- 텍스트 입력칸의 focusin 때만 편집 포커스를 요청합니다. 기존 대화 화면으로 사용자가 직접 이동한 경우에는 Back/키 처리를 위한 포커스를 확보하되 키보드를 자동으로 열지 않습니다. 잠금 해제나 프레임 콜백은 이 포커스를 요청하지 않습니다. 같은 속성의 반복 갱신은 생략합니다.
- 기존 일반/접근성 창 역할, WindowContext, 단일 WebView, retainedFrame/frameReady/visual callback과 흰 화면·렌더러 복구를 유지합니다. 정상 해제 중 창 제거/재부착·문서 재로드·등장 애니메이션·고정 대기·가림 화면을 추가하지 않았습니다. 권한 취소/생성 실패의 안전한 접근성 복귀는 유지합니다.

진단 사용법

1. 설정 → 잠금 해제 첫 화면 아래의 ‘잠금 해제 진단’을 켭니다. 기본값은 꺼짐이며 서비스 재시작과 ADB가 필요하지 않습니다.
2. 화면을 끄고 잠금을 해제합니다. 빠르게 다시 켜기 또는 오래 잠근 뒤 해제하기를 평소처럼 수행합니다.
3. 같은 설정에서 ‘로그 보기’로 확인하고 ‘로그 내보내기’를 누릅니다. Android 파일 저장 화면에서 위치를 고르면 실제 UTF-8 .txt 파일을 작성하고, 저장 완료/실패를 알립니다. 이 파일을 ChatGPT에 첨부할 수 있습니다.
4. ‘기록 삭제’로 내부 기록 전체를 삭제할 수 있습니다. 기록을 끄면 즉시 수집이 멈추며 다음에 켰을 때는 다음 화면 꺼짐부터 새 주기를 시작합니다.

진단 내용과 저장

- 화면 꺼짐/켜짐/USER_PRESENT, 관찰한 키가드 상태, 중복 이벤트, 잠금 해제 판단과 전환 종료 이유
- 실제 창 종류, add/remove/update 요청과 성공 반환, alpha 전후, visibility, 입력/포커스 플래그, 상태 전환, 창 포커스 콜백 및 실패·복구
- 시스템 창 ID·역할·활성·포커스, 알려진 키가드 ID 여부와 인터럽트/해제 과정 판정
- 시작 준비, DOM revision, frameReady/retainedFrame, visual callback, onDraw, attach/detach, 엔진 pause/resume와 문서/렌더러 복구
- Android/모델/앱 버전, 로컬 실제 시각과 단조 시간 경과, 주기별 생성·제거·갱신·alpha 변경 총횟수 및 상태 순서
- 요청(requested), 호출 성공 반환(accepted), 관찰/콜백(observed)을 구분합니다. update 성공·visual callback·onDraw는 시스템 화면 합성이 완료됐다는 뜻이 아닙니다.

앱 내부 전용 unlock-diagnostics.json에 최근 최대 5주기/190KB 이내로 보관합니다. 주기별 이벤트 수도 제한하며 과다 이벤트 생략 수를 표시합니다. 총횟수는 이벤트 생략과 별도로 유지합니다. 메모·질문/답변·사전 검색어·인증정보·화면 텍스트와 앱 패키지명은 기록하지 않습니다. 메모리 버퍼를 모아 단일 작업 스레드에서 원자적으로 저장하며 화면 전환마다 별도 파일이나 디스크 쓰기를 만들지 않습니다. 삭제 후 이전 비동기 쓰기가 기록을 되살리지 않도록 직렬 처리합니다. 외부 저장소 접근 권한은 추가하지 않았습니다.

진단을 꺼도 설정에서 권한/요청/현재 창과 마지막 잠금 해제 창·마지막 생성/갱신 실패를 확인할 수 있습니다.

보존 및 검증

시작화면 배치·여백·목적 목록·메모/ChatGPT/사전 영역과 색상은 그대로입니다. 기존 ChatGPT 즉시 진입·동일 방/질문/메시지 노드·재시도, 사전 반복 검색과 초안/포커스/스크롤 보존, 출처와 IME/키보드 배치 브라우저 회귀가 통과했습니다. 설정 진단 토글·보기·내보내기·삭제/취소와 편집 포커스 브리지 검사도 통과했습니다.

배포 작업은 관련 창/시스템 이벤트/렌더링/진단 보관·삭제/실제 텍스트 파일 내보내기와 기존 사전/ChatGPT/테마/타이머 JVM 검사 및 lint 후 release APK를 한 번 빌드하고 서명과 앱 ID를 확인해 게시합니다.

실기기 확인

One UI의 실제 합성과 반투명 전환의 최종 결과는 아직 확인하지 못했습니다. 이 변경은 로키가 정상 해제 때 수행하던 창 플래그 갱신과 새 System UI ID에 의한 숨김 경로를 제거합니다. 삼성 지문/PIN/패턴, 인증 전 비노출, 첫 버튼 터치·첫 텍스트 입력/키보드, 알림창/전화 및 빠른 재잠금은 기기에서 확인해야 합니다. 현상이 계속되면 위 진단을 켜서 .txt를 내보내면 로키의 alpha/창 갱신과 시스템 합성 가능성을 구분할 수 있습니다. 일반 Activity 전환은 도입하지 않았습니다.
