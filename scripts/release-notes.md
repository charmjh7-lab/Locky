Locky 1.2.4

기존 설치와 같은 앱 ID(com.locky.app)와 서명을 유지합니다.

- 화면 꺼짐 때 목적 순서를 바꾸기 위해 시작화면 전체를 render()하던 경로를 제거했습니다. 기존 목적 버튼 노드만 이동하므로 메모·ChatGPT·사전 입력창, 이벤트 연결, 선택과 목록 스크롤을 유지합니다. 목적 섞기 정책과 메모 자동 저장은 유지하며 저장 완료를 기다리느라 목적 갱신을 늦추지 않습니다.
- 실제 전체 렌더 또는 목적 순서 변경에만 DOM revision을 올립니다. 같은 revision의 nativeRestore/rendered 신호는 유효한 프레임을 무효화하지 않습니다. 내용이 달라지면 새 시각 프레임을 확인하고 오래된 navigation·revision·렌더러 콜백은 배제합니다.
- 빠르게 다시 잠금 해제해도 목적 갱신의 실제 JS 응답 전에는 이전 프레임을 노출하지 않습니다. 변경이 없으면 기존 프레임을 곧바로 재사용하고, 변경이 있으면 해당 프레임 준비 후 같은 오버레이를 노출합니다. 응답 유실은 기존 문서 생존 감시·프레임 복구 경로로 처리하며 정상 노출용 고정 지연은 추가하지 않았습니다.
- 정상 프레임 요청·완료에는 불필요한 Android 전체 레이아웃 요청을 생략하고 그리기만 요청합니다. 실제 attach/resume·초기 로딩 실패·콜백 지연·렌더러 종료 복구와 소프트웨어 렌더링은 유지합니다. onDraw를 숨겨진 창의 노출 전 필수 조건으로 사용하지 않습니다.
- 동일한 인셋·키보드 상태의 반복 전달에는 padding/viewport 갱신을 생략합니다. 실제 인셋·IME 변화는 기존대로 반영합니다. alpha와 입력 플래그는 기존처럼 한 번에 변경하며 동일 속성으로 창을 다시 갱신하지 않습니다.
- 잠금 중 투명·터치/포커스 불가·접근성 비노출, 단일 잠금 해제 전환과 시스템 UI 양보를 유지합니다. 사전 Activity·검색어 처리·직접 화면 잠금·앱 취소, 화면 배치·여백·메모 크기·테마·데이터 형식은 변경하지 않았습니다.
- 디버그 빌드에는 화면 꺼짐부터 DOM/프레임/창 노출/첫 그리기의 변경을 uptimeMillis로 기록하는 최대 40개 이벤트 진단을 제한했습니다. 입력 내용은 기록하지 않으며 릴리즈에서는 진단 호출과 로그가 컴파일되지 않습니다.

검증: 실제 app.js 브라우저 검사로 목적 노드·편집기 보존, 순서 변경, 메모 저장 중 부분 갱신, 커서/선택/스크롤, 변경 없는 준비, 앱 목적 선택, 사전 반복 검색·성공/실패 처리를 확인했습니다. 기존 키보드 검사도 통과했습니다. 배포 파이프라인에서 관련 JVM 검사, lint, 서명·앱 ID 검증을 통과한 릴리즈 APK만 게시합니다.

실기기 미검증: 삼성 One UI 지문/PIN/패턴 잠금 해제에서 다른 화면의 순간 노출과 번쩍임, 연속 화면 켜기·끄기, 알림창·최근 앱·권한·전화로 즉시 전환, 실제 키보드와 장시간 꺼짐 뒤 흰 화면 여부. Chromium의 그릴 준비 완료와 View.onDraw는 시스템 최종 합성 완료를 보장하지 않습니다. 잠금화면 위로 개인정보를 노출하거나 애니메이션 완료를 임의의 대기로 추정하지 않으며, 시각적 번쩍임이 완전히 사라졌다고 단정하지 않습니다.
