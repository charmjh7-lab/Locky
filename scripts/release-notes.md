기존 앱 ID(com.locky.app)와 서명을 유지합니다.

잠금 해제 첫 화면
- 다른 앱 위에 표시 권한이 허용되면 휴대폰 시작 창에는 TYPE_APPLICATION_OVERLAY, 관리 앱 차단에는 기존 TYPE_ACCESSIBILITY_OVERLAY를 사용합니다. 같은 WebHost/WebView를 유지하고 창 역할 변경은 화면 꺼짐·숨김 시점에 수행합니다.
- 준비된 일반 오버레이는 Android 잠금 정책 아래에서 불투명한 상태를 유지합니다. 정상적으로 준비된 경우 잠금 해제에는 alpha 변경 대신 입력 활성화만 반영합니다. 잠금 중에는 터치·포커스·접근성 노출을 차단하고 FLAG_SECURE를 사용하며 잠금화면 표시·해제 우회 플래그는 사용하지 않습니다.
- 설정 또는 권한·배터리 설정에서 다른 앱 위에 표시를 허용할 수 있습니다. ‘잠금화면 뒤에서 시작화면 준비’를 끄면 기존 방식으로 복귀합니다. 권한 미허용·취소·창 생성 거부 시에도 접근성 방식으로 안전하게 작동합니다. 권한 허용만으로 보고 있는 창을 즉시 교체하지 않습니다.
- AOSP의 창 계층과 keyguard 숨김 정책을 확인한 구현입니다. 삼성 One UI에서 잠금 해제 애니메이션과 같은 프레임에 노출되는지, 실제 잠금 중 개인정보가 시스템 정책대로 가려지는지는 실기기 확인이 필요합니다.

빠른 ChatGPT 질문
- 전송 즉시 현재 WebView에 기존 대화 UI·사용자 질문·접수 진행 상태를 표시합니다. newChat/send/state 응답이나 메모 저장을 기다리지 않고 MainActivity를 자동 실행하지 않습니다.
- 전송 요청 UUID를 실제 대화 ID로 사용합니다. 대화 생성·사용자 메시지·답변 자리·요청 매핑을 한 SQLite 트랜잭션으로 접수하고 기존 AI 스트리밍 엔진을 실행합니다. 저장 실패는 전체 롤백되며 응답 지연 후 같은 요청을 재시도해도 중복 저장·중복 AI 요청이 발생하지 않습니다.
- 임시 말풍선을 저장된 메시지 ID에 연결하여 같은 노드를 유지합니다. 늦은 접수 응답은 이미 표시한 최신 답변을 덮어쓰지 않습니다. 실패는 대화 안에 표시하고 동일 질문으로 재시도합니다. AI 실패 후 명시적 재시도도 기존 사용자/답변 행을 재사용합니다.
- 내부 화면 이동을 native navigation/pendingScreen/pendingChat 및 DOM revision과 동기화합니다. 이미 표시 중인 정상 문서는 새 프레임 확인 중에도 창을 유지하며, 최초 준비·분리·렌더러 오류 복구는 기존 검증을 기다립니다.
- 대화 목록·추가 질문·출처·취소·시작화면 복귀를 유지합니다. 화면 꺼짐은 다음 시작화면을 준비하며 AI 요청과 저장된 대화는 유지합니다. 사용자가 실제 다른 앱으로 이동하면 내부 대화 오버레이를 종료하고 기존 앱 차단 정책에 넘깁니다.

보존: 목적 부분 재배치, 메모 저장, 사전 검색/동일 WebView 전달/검색어 삭제, 그냥 끄기, 세션·타이머, 소프트웨어 렌더링과 흰 화면 복구. 시작화면 배치·여백·메모 크기·글자·테마와 기존 ChatGPT 디자인은 변경하지 않았습니다.

검증: 실제 app.js의 즉시 진입·저장 보류·말풍선 연결·늦은 응답·실패/중복 재시도·화면 꺼짐 후 응답·대화 재열기, 기존 사전/목적/메모 회귀와 ChatGPT 출처/IME 브라우저 검사를 통과했습니다. 배포 파이프라인에서 관련 JVM 회귀, lint, 서명·앱 ID 검증을 거친 APK만 게시합니다.

실기기 확인 필요: 삼성의 지문/PIN/패턴과 잠금화면·AOD·알림/수신 전화에서 개인정보 비노출, 실제 창 합성 및 번쩍임, 권한 허용/취소, 최근 앱·권한창·사전·키보드, 실제 계정의 스트리밍/중지/재시도. 실기기 번쩍임이 완전히 사라졌다고 단정하지 않습니다. 기기에서 새 표시 방식이 불안정하면 설정에서 기존 방식으로 즉시 복귀할 수 있습니다.
